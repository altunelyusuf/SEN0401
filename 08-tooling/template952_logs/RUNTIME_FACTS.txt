How the page runs code today, and what the chapter library needs (measured 2026-10-22 on page 9.51.1 code and on the 9.52.0 scratch page; Playwright 1.56.0, Chromium)

HOW THE PAGE RUNS CODE (template 9.51.1, kept unchanged in 9.52.0)
1. CPython compiled to WebAssembly (Pyodide 0.28.2, CPython 3.13.2) inside a Web Worker, loaded from https://cdn.jsdelivr.net/pyodide/v0.28.2/full/ on the first Run. It needs the network (the page test caches the CDN files). A program still running after 15 s is stopped by ending the worker.
2. The chapter library reaches that Python through the page data: pywheels_vX.json of the chapter folder names wheels (their bytes are embedded in the page as hexadecimal, py_wheels), packages for loadPackage (py_packages) and a boot snippet (py_boot). The worker unpacks every wheel into site-packages and runs the boot snippet once, so names such as L, K, R are ready in every program. Chapters 8 to 14 use this; chapters 5 and 6 have no pywheels file today, which is why their deck code cannot run in the Playground.
3. If workers are unavailable the page falls back to Brython 3.14.3 (also from jsdelivr) on the page thread; that fallback has no wheels, so the chapter library is NOT available there.
4. Each run: textarea code is parsed with ast, the last expression is evaluated and printed with repr(); stdout and stderr are captured; input() reads from the Input lines box.
The 9.52.0 chapter-code tab uses the same runPy(), so an example runs exactly as a Playground program with the same boot.

WHAT THE CHAPTER LIBRARIES NEED (read from 08-tooling, tested in the page's Pyodide)
- sen0401_ch06_tx_lib_v1_0_0.py: imports hashlib and struct only (sha256, no ripemd160, no pbkdf2): runs in Pyodide as it is, packaged as a wheel like chapters 8 to 14.
- sen0401_ch05_wallet_lib_v1_1_0.py: imports hashlib, hmac, os, unicodedata. Measured in the page's Pyodide 0.28.2: hashlib.new('ripemd160', ...) -> ValueError: unsupported hash type ripemd160 (line 49, hash160); hashlib.pbkdf2_hmac -> AttributeError: module 'hashlib' has no attribute 'pbkdf2_hmac' (line 100, the BIP39 seed). hmac with sha512, sha256/sha512, sha3 and unicodedata work. The library also opens HERE/ch05-evidence/bip39_english.txt (line 74), so the wheel must carry that folder (as chapter 9's wheel carries ch09-evidence). Therefore a chapter 5 page needs, in its boot snippet or wheel, a pure-Python RIPEMD-160 and a pure-Python PBKDF2-HMAC (built on hmac) registered before the library is imported, plus the evidence file in the wheel. Without them every example that calls hash160 or the seed function fails in the browser.
