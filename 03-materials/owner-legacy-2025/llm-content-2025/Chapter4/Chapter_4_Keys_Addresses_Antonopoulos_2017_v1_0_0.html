Introduction to Bitcoin Cryptography

What is Cryptography?

Cryptography (from Greek "secret writing") encompasses techniques for secure communication and data protection. Modern cryptography extends beyond encryption to include:

  • Digital Signatures: Proving knowledge of a secret without revealing it
  • Digital Fingerprints: Proving data authenticity
  • Key Exchange: Secure communication channel establishment
  • Zero-Knowledge Proofs: Proving statements without revealing underlying data
Bitcoin's Unique Use

Ironically, Bitcoin does NOT encrypt transaction data. The blockchain is completely transparent. Instead, Bitcoin uses cryptography for:

  1. Access Control: Who can spend which bitcoins
  2. Ownership Proof: Digital signatures show authorization
  3. Identity Management: Pseudonymous addresses protect privacy
Think About It

If transactions aren't encrypted, how does Bitcoin maintain security? The answer: cryptographic signatures ensure only private key holders can authorize spending.

Public Key Cryptography Fundamentals

Historical Context: Public key cryptography was invented in the 1970s by Whitfield Diffie and Martin Hellman, revolutionizing information security.

The Problem Solved: Traditional symmetric encryption requires both parties to share a secret key securely. This creates a chicken-and-egg problem: how do you securely share the key in the first place?

The Solution: Asymmetric cryptography uses two related but distinct keys:

  • Private Key: Kept secret, never shared
  • Public Key: Freely distributed to anyone

Mathematical Foundation

Based on mathematical functions that are:

  • Easy in one direction: Computing f(x) is fast
  • Hard in reverse: Computing x from f(x) is computationally infeasible

Examples of One-Way Functions:

  1. Prime Factorization: Easy to multiply primes (7 × 13 = 91), hard to factor (91 = ? × ?)
  2. Discrete Logarithm: Easy to compute gx mod p, hard to find x
  3. Elliptic Curve Multiplication: Easy to compute k × G, hard to find k (Bitcoin uses this!)

Elliptic Curve Cryptography (ECC)

Why ECC? Provides same security as RSA with much smaller keys:

  • RSA 2048-bit ≈ ECC 224-bit (same security level)
  • Smaller keys → smaller transactions → lower fees

Bitcoin's Choice: secp256k1 elliptic curve

  • Standardized curve (SEC 2)
  • 256-bit security
  • Optimized for efficient computation
  • No known backdoors or weaknesses
The Elliptic Curve Equation 
y² = x³ + 7  (over finite field F(p))

where p = 2²⁵⁶ - 2³² - 2⁹ - 2⁸ - 2⁷ - 2⁶ - 2⁴ - 1

Private Keys: The Foundation of Ownership

What is a Private Key?

A private key is simply a 256-bit number chosen at random. This number is the ultimate source of control in Bitcoin. Anyone who knows your private key can spend your bitcoin.

Critical Security Principle

"Not your keys, not your coins" - If you don't control the private key, you don't truly own the bitcoin. Key loss = permanent bitcoin loss. There is NO recovery mechanism.

Private Key Format

A private key can be represented in various formats:

Format Example Use Case
Hex E9873D79C6D87DC0FB6A5778633389F4453213303DA61F20BD67FC233AA33262 Programming, debugging
WIF 5Kb8kLf9zgWQnogidDA76MzPL6TsZZY36hWXMssSzNydYXYB9KF Import/export, paper wallets

Decimal 105738... (77 digits) Mathematical operations

Generating Secure Private Keys

The security of Bitcoin depends entirely on the randomness of private key generation. A private key must be:

  1. Truly Random: Generated using cryptographically secure random number generator (CSPRNG)
  2. Uniformly Distributed: All 2²⁵⁶ possible values equally likely
  3. Unpredictable: No pattern or correlation with other keys
Common Misconception

NEVER create a private key by typing random characters or using a weak random number generator. Attackers can crack weak keys! Always use:

  • Hardware wallet random number generators
  • Cryptographically secure libraries (e.g., Python's secrets module)
  • Physical entropy sources (dice rolls, coin flips - but requires 256 flips!)

Private Key Space

The private key space is enormous: 2²⁵⁶ possible keys

To put this in perspective:

2²⁵⁶ ≈ 10⁷⁷ (1 followed by 77 zeros)

Comparison:
- Atoms in observable universe: ~10⁸⁰
- Grains of sand on Earth: ~10¹⁸
- Stars in Milky Way: ~10¹¹

Probability of collision: effectively ZERO
Security Guarantee

The chance of two randomly generated private keys being identical is so astronomically small that it's considered impossible. You can safely generate a key knowing it's virtually certain to be unique.

Public Keys: Derived from Private

Public Key Generation

A public key is mathematically derived from a private key using elliptic curve multiplication:

K = k × G

where:
K = Public key (a point on the curve)
k = Private key (a 256-bit number)
G = Generator point (constant for secp256k1)

Key Property: This operation is a one-way function:

  • ✅ Easy: Given k, compute K (milliseconds)
  • ❌ Hard: Given K, find k (impossible with current technology)

Public Key Formats

Public keys can be represented in two formats:

1. Uncompressed Public Key (65 bytes)

04 [x-coordinate: 32 bytes] [y-coordinate: 32 bytes]

Example:
04A0DC65FFCA799873CBEA0AC274015B9B5F0B8C0E4D6E13CBD0FA8C0EC2E5D3...
  └─ prefix (0x04)
     └──────────────── x ───────────────┘
                                        └──────────── y ───────────┘

2. Compressed Public Key (33 bytes)

Modern wallets use compressed keys to save space:

02 [x-coordinate: 32 bytes]  (if y is even)
03 [x-coordinate: 32 bytes]  (if y is odd)

Example:
02A0DC65FFCA799873CBEA0AC274015B9B5F0B8C0E4D6E13CBD0FA8C0EC2E5D3
└─ prefix (0x02)
   └──────────────────────── x ───────────────────────┘
Why Compression Works

Given the elliptic curve equation y² = x³ + 7, if we know x, we can calculate y² and take the square root. This gives two possible y values (positive and negative). The prefix (02 or 03) indicates which one.

Space Savings: 65 bytes → 33 bytes (49% reduction)

Point Addition on Elliptic Curves

The "multiplication" k × G is actually repeated addition of the generator point to itself k times:

1 × G = G
2 × G = G + G
3 × G = G + G + G
...
k × G = G + G + ... + G (k times)

However, we use efficient algorithms (double-and-add) to compute this in logarithmic time rather than linear time.

Bitcoin Addresses: User-Friendly Identifiers

What is a Bitcoin Address?

A Bitcoin address is a user-friendly representation of the public key, created through a series of cryptographic hashing and encoding steps. Think of it as the "account number" where others can send you bitcoin.

Why Not Use Public Keys Directly?
  • Shorter: Addresses are shorter and easier to share
  • Error Detection: Built-in checksum catches typos
  • Additional Security: Double hashing provides extra protection
  • Script Flexibility: Addresses can represent various spending conditions

Address Generation Pipeline

The complete process from private key to address:

Private Key (256 bits)
    ↓ [Elliptic Curve Multiplication]
Public Key (264 bits uncompressed or 264 bits compressed)
    ↓ [SHA-256]
SHA-256 Hash (256 bits)
    ↓ [RIPEMD-160]
Public Key Hash (160 bits)
    ↓ [Add version prefix]
Versioned Hash (168 bits)
    ↓ [SHA-256 twice for checksum]
Checksum (32 bits, first 4 bytes)
    ↓ [Base58Check Encoding]
Bitcoin Address (25-34 characters)

Address Types

1. Legacy Address (P2PKH - Pay to Public Key Hash)

  • Prefix: Starts with 1
  • Example: 1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa
  • Use: Original Bitcoin address format
  • Size: 25-34 characters

2. Script Hash Address (P2SH - Pay to Script Hash)

  • Prefix: Starts with 3
  • Example: 3J98t1WpEZ73CNmYviecrnyiWrnqRhWNLy
  • Use: Multisignature and complex scripts
  • Feature: Moves script complexity from sender to receiver

3. SegWit Address (Bech32)

  • Prefix: Starts with bc1
  • Example: bc1qw508d6qejxtdg4y5r3zarvary0c5xw7kv8f3t4
  • Use: Native SegWit (Segregated Witness)
  • Benefits: Lower fees, better error detection, case-insensitive
Feature P2PKH (1...) P2SH (3...) Bech32 (bc1...)
Introduced 2009 2012 2017
Transaction Size Large Medium Small
Fees High Medium Low (10-40% savings)
Error Detection Basic Basic Advanced
Compatibility Universal Universal Modern wallets only

Base58Check Encoding

Bitcoin uses Base58Check encoding for addresses (P2PKH and P2SH types):

Base58 Alphabet (58 characters):
123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz

Excluded characters (to avoid confusion):
0 (zero) - looks like O
O (uppercase o) - looks like 0
I (uppercase i) - looks like l
l (lowercase L) - looks like I
Checksum Protection

Base58Check adds a 4-byte checksum (first 4 bytes of double SHA-256 hash) to detect typos:

  • Catches nearly all single-character errors
  • Catches most transposition errors
  • Probability of accepting invalid address: ~1 in 4 billion

Bitcoin Wallets: Key Management Systems

What is a Bitcoin Wallet?

Despite the name, a Bitcoin wallet doesn't actually "store" bitcoin. Instead, it:

  • Stores private keys that control access to bitcoin addresses
  • Generates new addresses for receiving payments
  • Creates and signs transactions to send bitcoin
  • Tracks balance by scanning the blockchain
Key Concept

Bitcoin doesn't exist in wallets - it exists as entries on the blockchain. Your wallet is just a keychain that proves ownership of those blockchain entries.

Hierarchical Deterministic (HD) Wallets

Modern wallets use HD wallet technology (BIP-32, BIP-44) that generates all keys from a single seed:

Seed (128-256 bits random)
    ↓ [Mnemonic encoding - BIP-39]
12-24 Word Phrase
    ↓ [Key Derivation - BIP-32]
Master Private Key
    ↓ [Hierarchical derivation]
Child Keys (billions of keys from one seed)

Advantages of HD Wallets

  • Single Backup: One seed backs up unlimited keys
  • Organizational Structure: Keys organized in tree hierarchy
  • Account Isolation: Separate keys for different purposes
  • Extended Public Keys: Generate receive addresses without private keys

Mnemonic Code Words (BIP-39)

HD wallets use human-readable mnemonic phrases instead of random hex strings:

Example 12-word phrase:
witch collapse practice feed shame open despair creek road again ice least

Example 24-word phrase:
void come effort suffer camp survey warrior heavy shoot primary clutch
crush open amazing screen patrol group space point ten exist slush
involve unfold
Security Critical

Your mnemonic phrase IS your wallet. Anyone with these words controls all your bitcoin. Never:

  • Store it digitally (photos, cloud, email)
  • Share it with anyone
  • Enter it on websites claiming to "verify" or "restore" your wallet

DO: Write it on paper, store in secure location (safe, safety deposit box)
