Introduction

Bitcoin as Decentralized System

Bitcoin, introduced via Satoshi Nakamoto's 2008 whitepaper, fundamentally transformed digital currencies by proving electronic cash could function without centralized authority. The Bitcoin network provides infrastructure for discovering, propagating, validating, and recording transactions across thousands of independent global participants.

Key Concepts

  • Peer-to-peer architecture eliminates single points of failure
  • Decentralized control emerges from collective actions
  • No central authority required for transactions
  • Cryptographic verification replaces institutional trust
  • Global consensus without coordination servers
P2P Node Connection Demo
class P2PNode:
    def __init__(self, id):
        self.id = id
        self.peers = []
    
    def connect(self, peer):
        self.peers.append(peer)
        print(f"{self.id} → {peer.id}")
    
    def broadcast(self, msg):
        for p in self.peers:
            print(f"{self.id} sends to {p.id}: {msg}")

alice, bob, carol = P2PNode("Alice"), P2PNode("Bob"), P2PNode("Carol")
alice.connect(bob); alice.connect(carol)
alice.broadcast("New block!")

Philosophical Foundations

Decentralization Principle

Decentralization guides Bitcoin's architecture, distributing power across participants rather than concentrating it. This reflects fundamental philosophy about power distribution, censorship resistance, and protection against single-point failures.

ControlSingle authorityDistributed across all

Peer Equality

All nodes maintain equal status without hierarchy. No node has intrinsic authority—validation power is equal for all participants regardless of computational power or wealth.

Network Architecture

Core P2P Network

The core Bitcoin network comprises nodes running the P2P protocol—approximately 15,000-17,000 total nodes globally, with 6,000-8,000 publicly accessible listening nodes. These full nodes independently validate all transactions and blocks.

Network Components

  • Core P2P network of full validating nodes
  • Extended network with specialized protocols
  • Relay networks for low-latency mining
  • Edge components for service integration

Node Types

Full Nodes

Full nodes maintain complete blockchain copies (550+ GB), independently validate all transactions and blocks, and provide four core services: routing, blockchain storage, optional mining, and wallet services.

SPV Nodes

Simplified Payment Verification nodes store only block headers (~75 MB), enabling lightweight operation on mobile devices. SPV nodes verify payments through merkle proofs without complete blockchain copies.

SPV Merkle Proof Verification
import hashlib

def hash(data): return hashlib.sha256(data.encode()).hexdigest()[:8]
def merkle_root(txs): return hash(hash(txs[0])+hash(txs[1]))

# Block with 4 transactions
txs = ["Alice→Bob", "Carol→Dave", "Eve→Frank", "Grace→Henry"]
root = merkle_root([merkle_root(txs[:2]), merkle_root(txs[2:])])

print(f"Merkle Root: {root}")
print("SPV node verifies with proof, not full transactions!")

Mining Nodes

Mining nodes perform Proof-of-Work computations using specialized ASIC hardware. Pool mining coordinates thousands of participants, distributing rewards proportionally to contributed hash power.

Network Protocols

Bitcoin P2P Protocol

The P2P protocol operates over TCP (port 8333 mainnet) with standardized message structures enabling peer discovery, transaction/block propagation, and blockchain synchronization. Messages include: inv (inventory announcements), getdata (data requests), tx (transactions), block (blocks), addr (peer addresses).

Transaction Propagation

Inventory-based propagation minimizes redundant transmission. Nodes announce transaction IDs via inv messages; peers request unknowns via getdata; originating nodes send complete transactions. This reduces bandwidth by ~95%.

Block Propagation

Compact block relay (BIP-152) exploits mempool synchronization—sending block headers plus short transaction IDs rather than full data. High-bandwidth mode eliminates inv delays for trusted peers, achieving near-minimum latency.

Security & Privacy

Eclipse Attack Defenses

Eclipse attacks isolate victims by monopolizing connections. Bitcoin defends via connection diversity (across network groups), address database management, and new/tried table separation preventing immediate pollution.

Encryption & Authentication

BIP-150 enables peer authentication via cryptographic identity proof. BIP-151 proposes end-to-end encryption protecting against traffic analysis. Tor integration conceals IP addresses from network observers.
