1.1 What is a Transaction?

Tier 1
Definition: A transaction is a data structure that encodes the transfer of value between participants in the Bitcoin system. Each transaction is a public entry in Bitcoin's blockchain, the global double-entry bookkeeping ledger.

Transactions are the most important part of the bitcoin system. Everything else in bitcoin is designed to ensure that transactions can be created, propagated on the network, validated, and finally added to the global ledger of transactions (the blockchain).

A transaction contains several key components:

  • Version: Specifies the transaction format version number
  • Inputs (vin): An array of transaction inputs that reference previous transaction outputs being spent
  • Outputs (vout): An array of transaction outputs that create new spendable amounts
  • Locktime: Defines the earliest time or block height when the transaction can be added to the blockchain

Transaction ID (TXID): Each transaction has a unique identifier calculated as the double SHA256 hash of the transaction data. This serves as a permanent, unchangeable reference to the transaction.

💡 Real-World Example

Think of a Bitcoin transaction like a check. Just as a check specifies who is paying (the account it's drawn from), how much is being paid, and who receives the payment, a Bitcoin transaction specifies:

  • Inputs: Which previous outputs (your "account balance") you're spending from
  • Outputs: Where the bitcoin is going and how much
  • Change: Any leftover amount returned to you (like getting change from a cashier)

Python Example: Calculating Transaction ID 
import hashlib
import json

def calculate_txid(tx_data):
    """
    Calculate Transaction ID from transaction data.
    TXID = SHA256(SHA256(serialized_transaction))
    
    Args:
        tx_data: Dictionary containing transaction structure
        
    Returns:
        Hexadecimal TXID string (reversed for display)
    """
    # Serialize transaction (simplified for demonstration)
    tx_serialized = json.dumps(tx_data, sort_keys=True).encode()
    
    # First SHA256 hash
    first_hash = hashlib.sha256(tx_serialized).digest()
    
    # Second SHA256 hash (double hash)
    second_hash = hashlib.sha256(first_hash).digest()
    
    # Reverse byte order for display (Bitcoin convention)
    txid = second_hash[::-1].hex()
    
    return txid

# Example transaction structure
example_tx = {
    "version": 1,
    "inputs": [{
        "prev_txid": "7957a35fe64f80d234d76d83a2a8f1a0d8149a41d81de548f0a65a8a999f6f18",
        "vout": 0,
        "scriptSig": "304502...0484ecc0...",
        "sequence": 4294967295
    }],
    "outputs": [
        {
            "value": 1500000,  # 0.015 BTC in satoshis
            "scriptPubKey": "OP_DUP OP_HASH160 ab68025513c3dbd2f7b92a94e0581f5d50f654e7 OP_EQUALVERIFY OP_CHECKSIG"
        },
        {
            "value": 8450000,  # 0.08450 BTC in satoshis (change)
            "scriptPubKey": "OP_DUP OP_HASH160 7f9b1a7fb68d60c536c2fd8aeaa53a8f3cc025a8 OP_EQUALVERIFY OP_CHECKSIG"
        }
    ],
    "locktime": 0
}

# Calculate and display TXID
txid = calculate_txid(example_tx)
print(f"Transaction ID: {txid}")
print(f"\\nTransaction Details:")
print(f"  Inputs: {len(example_tx['inputs'])}")
print(f"  Outputs: {len(example_tx['outputs'])}")
print(f"  Total Input: 0.1 BTC (from previous output)")
print(f"  Payment: {example_tx['outputs'][0]['value'] / 100000000:.8f} BTC")
print(f"  Change: {example_tx['outputs'][1]['value'] / 100000000:.8f} BTC")
print(f"  Implied Fee: 0.001 BTC")

What is a Transaction ID (TXID)?

Understanding how transactions are uniquely identified in the Bitcoin network

✅ Correct! Here's why:

The Transaction ID (TXID) is calculated as the double SHA256 hash of the serialized transaction data. This creates a unique, permanent identifier for each transaction that cannot be altered without changing the entire transaction.

Key Points:

  • The TXID is derived from ALL transaction data (inputs, outputs, locktime, etc.)
  • Double hashing (SHA256 twice) provides additional security
  • The bytes are reversed for display (Bitcoin convention)
  • Any modification to the transaction changes the TXID

1.2 The UTXO Model

Tier 1
UTXO (Unspent Transaction Output): An indivisible chunk of bitcoin currency recorded on the blockchain and recognized as valid by the entire network. The UTXO set represents all currently spendable bitcoins.

Bitcoin uses an Unspent Transaction Output (UTXO) model rather than an account-based system like traditional banking. This fundamental difference affects how transactions are constructed and validated.

Key Characteristics:

  • Indivisible: UTXOs cannot be partially spent; they must be consumed entirely
  • Discrete: Each UTXO has a specific value in satoshis
  • Trackable: Full nodes track all UTXOs in the UTXO set (currently millions)
  • State-Based: Every transaction represents a state transition in the UTXO set

UTXO vs Account Model:

Aspect UTXO Model (Bitcoin) Account Model (Ethereum)
State Storage Set of unspent outputs Account balances
Transaction Consumes UTXOs, creates new UTXOs Debits one account, credits another
Partial Spending Not possible (must create change output) Directly supported
Privacy Better (multiple addresses/outputs) Lower (account history visible)

Wallet Balance: What we call a "wallet balance" is actually the sum of all UTXOs that the wallet can spend with its private keys. Wallets scan the blockchain to aggregate UTXO values.

💡 The Change-Making Analogy

Imagine buying a $1.50 coffee with physical currency:

  • Exact Change: One $1 bill + two quarters = $1.50 (like using exact UTXO)
  • Making Change: Give $5 bill → Receive $3.50 change (like consuming large UTXO, creating payment + change outputs)
  • Cannot Split: You can't tear a $5 bill in half (UTXOs are indivisible)

Similarly, if you have a 0.5 BTC UTXO and want to pay 0.015 BTC, you must:

  1. Consume the entire 0.5 BTC UTXO as input
  2. Create 0.015 BTC output to recipient
  3. Create ~0.484 BTC change output back to yourself
  4. Leave ~0.001 BTC as transaction fee
